Realistic failure patterns

The model does not need to crash to be wrong.

Malformed JSON

The next module expects a number and status field. The LLM returns prose or null, but the flow still reaches a CRM write.

Confident wrong classification

An ambiguous lead/document is classified incorrectly and the automation treats the result as fact instead of routing to review.

Unsafe finance/document action

An extracted amount or identifier is wrong, but no deterministic validation or human approval exists before downstream action.

Customer message after takeover

A human starts handling the conversation, but scheduled AI follow-up remains active and sends another message.

Retry duplicates action

The same validated AI result is replayed after a timeout and creates the same CRM/email/document side effect twice.

Fallback looks like success

An error handler supplies substitute data and downstream modules cannot distinguish fallback output from a real AI result.
