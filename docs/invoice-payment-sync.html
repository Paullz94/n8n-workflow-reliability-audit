Realistic failure patterns

Small sync errors can become expensive accounting work.

Duplicate invoice

An invoice API commits successfully but the response times out. Make retries and creates a second invoice because there is no stable idempotency key.

Partial payment marked paid

A €2,000 invoice receives €500. The workflow checks only “payment event received” and closes the CRM deal as fully paid.

Wrong customer

Customer matching uses company name instead of a stable identifier and attaches an invoice/payment to the wrong account.

Half-finished sync

QuickBooks updates, then the CRM write fails. Finance and sales now see different truth.

Refund ordering

A refund/cancellation event arrives after a later state update and overwrites the newer business state.

Sync loop

CRM updates accounting, accounting triggers CRM, and the same change bounces between systems.
