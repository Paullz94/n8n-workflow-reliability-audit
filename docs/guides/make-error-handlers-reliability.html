Make.com reliability guide

Error handlers can save a scenario — or hide the failure.

The important question is not simply whether a scenario has an error handler. It is what happens to the business event when that module fails.

Platform success is not the same as business success. A scenario can continue after an error while the important external side effect never happened.

Skip / Ignore

Skip/Ignore can discard the failed bundle and allow later bundles to continue. That may be intentional for malformed optional records, but it can become silent data loss when the bundle represents business work that must happen.

Ask
Is losing this failed event acceptable?
Detect
Can an operator see that it was skipped?
Verify
Force a synthetic failure and confirm the missing action becomes visible somewhere operators actually monitor.

Resume

Resume can substitute output for a failed module and let downstream processing continue. The risk is that downstream success is mistaken for proof that the failed write itself succeeded.

Ask
Can downstream modules distinguish real output from fallback output?
Verify
Make the write fail on synthetic data and inspect whether later modules can falsely imply success.

Commit

Commit intentionally preserves earlier transactional changes before the run stops. Partial state is not automatically wrong; the reliability question is whether that partial state is understood and reconcilable.

Rollback

Rollback only applies within the transaction boundaries supported by Make and the underlying modules. Previously committed or non-transactional external effects may not be reversible.

Break and retry

Retry is essential for transient failures, but it becomes dangerous around external writes. A request may have committed remotely even if the caller never received a clean response.

Prevent
Use an idempotency key, stable business key, upsert or equivalent destination-specific guard.
Verify
Replay the same synthetic event and confirm the intended external state exists only once.

Scenario-level settings matter too

Parallel webhook execution, incomplete-execution settings and data-loss behavior change the recovery model around the same module graph.
